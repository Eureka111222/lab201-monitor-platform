**RBAC 模块 (User-Role-Relation)**:

- **原理**：解耦“人”与“权”。通过中间表 `sys_user_role`，一个用户可以有多个角色，一个角色可以对应多个用户。
- **扩展性**：未来如果需要加入“设备管理员”（只能重启机器不能看文档），只需在 `sys_role` 加一条记录，并在代码里配置对应权限即可，无需改表结构。

**服务器资产 (Server_Node)**:

- **原理**：**“动静分离”策略的“静”部分**。
- **JSON 的妙用**：`cuda_info` 使用 JSON 存储是本设计的亮点。因为 CUDA 版本列表是一个**结构化但非关系型**的数据（只用于前端展示，不做复杂SQL查询），用 JSON 避免了建立 `server_cuda_relation` 这种琐碎的子表，开发效率极高。
- **心跳机制**：`last_heartbeat` 字段配合定时任务，替代了旧的 `online` 表，实现了**状态的实时感知**。

**监控流水 (Gpu_Metric_Log)**:

- **原理**：**“动静分离”策略的“动”部分**。这是一个典型的**时序数据 (Time-Series Data)** 表。
- **索引策略**：`KEY idx_server_time (server_name, create_time)` 是为了满足你“查询近7天趋势”的需求。这个联合索引能让百万级数据查询瞬间完成。
- **冗余设计**：虽然有了 `server_node`，但在日志表里依然冗余存储 `server_name`（而不是存 ID），是为了方便 Python 脚本上报（脚本只知道 hostname，不知道 ID），减少了一次查 ID 的交互。

**知识库 (Sys_Document)**:

- **原理**：**元数据管理**。它是连接 MySQL（业务）、MinIO（文件实体）、Milvus（向量数据）的枢纽。删除一条记录时，必须根据这里的 ID 去同步删除另外两个库的数据，保证数据一致性。
